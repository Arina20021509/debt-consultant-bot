# debt-bot — AI-консультант по списанию долгов

Демо-проект Арины для портфолио и собеседований (AI-внедрение, чат-боты, conversational AI).
RAG-бот на GigaChat: отвечает по базе знаний о банкротстве граждан, оформляет заявку юристу, работает в Telegram и консоли на русском и узбекском. Описание и метрики — в README.md, его читают работодатели.

## Как общаться с Ариной

- По-русски, просто и по шагам: Арина осваивает разработку, код пишет Claude, она ставит задачи и тестирует.
- Объясняй, *почему* сделано так, а не иначе: каждое решение — потенциальная история для собеседования.
- Перед изменениями, которые видят клиенты бота, коротко скажи, что поменяется.

## Запуск (Windows, PowerShell)

```
cd $HOME\projects\debt-bot
.venv\Scripts\python.exe -m bot.telegram_bot   # Telegram-бот
.venv\Scripts\python.exe -m bot.chat           # консоль: /debug, /заявка, /new, /ru, /uz
.venv\Scripts\python.exe -m bot.evaluate       # тесты на русском (32 вопроса)
.venv\Scripts\python.exe -m bot.evaluate uz    # тесты на узбекском (12 вопросов)
```
Для вывода кириллицы в консоль ставь `$env:PYTHONIOENCODING = "utf-8"`. Полный прогон тестов идёт 5–10 минут — запускай в фоне.

**Telegram-бот должен работать в одном экземпляре.** Перед запуском проверь и останови старые процессы (`python.exe` с `bot.telegram_bot` в командной строке), иначе два бота конфликтуют на одном токене. Остановленный процесс фоновой задачи отчитается как «failed» — это нормально.

## Устройство

- `bot/kb.py` — нарезка базы `knowledge/*.md` по заголовкам `##`, поиск BM25 (слова обрезаются до 4 букв), перевод вопроса на русский, переформулирование запроса через LLM.
- `bot/prompts.py` — системный промпт: роль, правила (только по базе, не выдумывать цифры, все условия), 3 few-shot примера.
- `bot/dialog.py` — диалог одного клиента, общий для Telegram и консоли; сохраняется через pickle (индекс базы исключается).
- `bot/qualify.py` — заявка: вопросы задаёт код, LLM извлекает значения в JSON, контакт проверяется regex, оценку для юриста считает код; запись в `data/leads.xlsx`.
- `bot/i18n.py` — тексты интерфейса, вопросы заявки, валюта по языку (ru → RUB, uz → UZS).
- `bot/telegram_bot.py` — кнопки по этапам, выбор языка, уведомление юристу в чат `TELEGRAM_ADMIN_CHAT_ID`, команды админа `/leads`, `/debug` (у админа `/start` сбрасывает отметку о заявке для повторных тестов).
- `bot/evaluate.py` — метрики: поиск (top-4), ответы с нужными фактами, честные отказы. Правила в csv: `&` — все, `|` — любой.

## Принципы, на которых держится проект

- **LLM понимает, код решает.** Модель: ответы, перевод, переформулирование, разбор свободных ответов. Правила: кнопки, телефон/@ник, пороги закона, подсказки юристу.
- **Одна задача — один вызов модели.** Дважды подтверждено замерами: «переведи и дополни синонимами» за раз давало 60% поиска на узбекском, отдельный шаг перевода — 100%; кредиторы в заявке не переводились, пока перевод не вынесли отдельно.
- **Метрики до и после.** Любое изменение промпта или поиска проверяй прогоном `bot.evaluate` и записывай результат в README (таблица «Как менялись метрики»).
- **Тест расширяем, только если ответ бота верный** (например, «три года» словами). Если ошибся бот — чиним бота. Известная оставшаяся ошибка: на вопрос про 600 тысяч модель иногда решает за клиента, что просрочка уже есть.
- **Валюта:** цены услуг в базе — в рублях, модель не должна их пересчитывать. Сумму долга клиент на узбекском называет в сумах; рублёвые пороги закона к ней не применяются.

## GigaChat

- Модель по умолчанию `GigaChat-3-Pro` (выбрана по метрикам из GigaChat-2, 2-Max, 3-Pro). Старое имя `GigaChat` даёт 404.
- Эмбеддинги в бесплатном тарифе — 402 Payment Required, поэтому поиск BM25 (эмбеддинги есть в коде, `RETRIEVER=embeddings`).
- Бывают таймауты и обрывы соединения: в `llm.py` таймаут 60 с и свои повторы на `httpx.TransportError`.
- Баланс токенов: `llm._giga().get_balance()`.

## Секреты и данные

- Ключи в `.env` (`GIGACHAT_CREDENTIALS`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`). **Никогда не выводи их значения** — проверяй только наличие и формат. `.env` и `data/` в `.gitignore`.
- `data/leads.xlsx` — заявки, `data/bot_state.pickle` — сохранённые диалоги. Не удаляй и не перезаписывай их в тестах: подменяй `qualify.LEADS_PATH` на временный файл.
