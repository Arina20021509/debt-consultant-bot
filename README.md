# Бот-консультант для сервиса по списанию долгов

Демо-проект: AI-консультант на GigaChat, который отвечает клиентам по базе знаний компании (RAG), не выдумывает ответы и оформляет заявку на консультацию с выгрузкой в Excel. Качество ответов проверяется автоматически на наборе тестовых вопросов.

Автор: Арина Бабич. Раньше я внедряла голосовых роботов холодного обзвона для сервиса по списанию долгов (9 роботов, 100–150 тыс. звонков в месяц, рост конверсии в заявку с 2,3% до 4,6%). Этот проект — следующий шаг: тот же клиентский сценарий, но на LLM.

## Задача

| | |
|---|---|
| **Пользователь** | Человек с долгами, который хочет понять, можно ли их списать, и боится ошибиться |
| **Проблема** | Вопросы типовые (сроки, цены, последствия, документы), но юристы тратят на них время, а ночью и в выходные ответить некому |
| **Сценарий** | Клиент задаёт вопросы в чате → бот отвечает только по проверенной базе знаний → если клиент готов, бот собирает данные и передаёт заявку юристу |
| **MVP** | Telegram-бот и консольный чат: ответы по базе знаний, квалификация заявки, уведомление юриста, выгрузка в Excel, автотест качества |
| **Метрики** | Точность поиска по базе, доля ответов с правильными фактами, доля честных отказов на вопросы вне базы |

## Как устроено

```
Вопрос клиента
   │
   ├─ хочет оставить заявку? ── да ──▶ Квалификация (workflow + LLM) ──▶ data/leads.xlsx
   │                                    вопросы задаёт код, LLM разбирает свободные ответы,
   │                                    предварительную оценку для юриста считает код по правилам
   нет
   │
   ▼
GigaChat дополняет вопрос синонимами и терминами («заплатить управляющему» → «вознаграждение, депозит»)
   │
   ▼
Поиск по базе знаний: BM25 по ключевым словам, top-4 фрагмента
   │
   ▼
GigaChat-3-Pro: роль консультанта + правила + найденные фрагменты + few-shot примеры
   │
   ▼
Ответ только по базе знаний или «уточню у юриста»
```

**Принципы:**
- **LLM понимает, код решает.** Модель отвечает на вопросы и разбирает свободный текст. Условия вроде «долг от 25 000 до 1 000 000 ₽» проверяет обычный код, а не модель.
- **Не выдумывать.** Если ответа нет в базе, бот говорит «уточню у юриста» и предлагает консультацию.
- **Без юридических обещаний.** Бот не говорит клиенту, спишут ли долги: это решает юрист. Предварительная оценка видна только юристу в Excel.

**Техники промптинга:** role prompting (роль и правила консультанта), grounding (ответ только по найденным фрагментам), few-shot (примеры ответа, когда информация есть, когда её нет и когда в базе нет конкретной суммы), переформулирование запроса перед поиском, низкая temperature для стабильности.

**Почему BM25, а не эмбеддинги.** Эмбеддинги GigaChat в бесплатном тарифе недоступны. Для базы из 31 фрагмента классический поиск по ключевым словам с переформулированием запроса через LLM дал 100% попаданий на тестовом наборе. Поиск по эмбеддингам тоже реализован и включается настройкой `RETRIEVER=embeddings`.

|---|---|
| `knowledge/` | База знаний: 5 документов, 31 фрагмент |
| `bot/kb.py` | Нарезка базы на фрагменты, переформулирование запроса, поиск (BM25 или эмбеддинги) |
| `bot/prompts.py` | Системный промпт и few-shot примеры |
| `bot/llm.py` | Подключение к GigaChat API |
| `bot/qualify.py` | Квалификация заявки и выгрузка в Excel |
| `bot/dialog.py` | Логика диалога, общая для Telegram и консоли |
| `bot/telegram_bot.py` | Telegram-бот: кнопки, уведомления юристу, команды администратора |
| `bot/chat.py` | Консольный чат |
| `bot/evaluate.py` | Автотест качества |
| `tests/questions.csv` | 32 тестовых вопроса: 27 по базе знаний и 5 вне её |

## Качество

Итоговый прогон `python -m bot.evaluate` на GigaChat-3-Pro:

| Метрика | Результат |
|---|---|
| Поиск нужного фрагмента (top-4) | **27/27 (100%)** |
| Ответы с нужными фактами | **26/27 (96%)** |
| Честные отказы на вопросы вне базы | **5/5 (100%)** |

### Как менялись метрики

| Шаг | Поиск | Ответы | Отказы |
|---|---|---|---|
| BM25, слова обрезаются до 6 букв | 74% | — | — |
| Обрезка до 4 букв (подобрано замером: 4 → 85%, 5 → 78%, 6 → 74%) | 85% | — | — |
| + переформулирование запроса через LLM | 96% | 81% | 100% |
| + правила против выдуманных цифр, третий few-shot пример, слово «госпошлина» в базе | 100% | 93–96% | 60–80% |
| Сравнение моделей на том же тесте | | | |
| — GigaChat-2 | 100% | 96% | 80% |
| — GigaChat-2-Max | 100% | 93% | 100% |
| — **GigaChat-3-Pro (выбрана)** | 100% | 96% | 100% |

**Что нашли тесты:**
- Бот назвал госпошлину «300 ₽», хотя в базе знаний суммы нет. Исправлено правилом в промпте и few-shot примером.
- Младшая модель GigaChat-2 иногда отвечала из собственных знаний («ограничений на регистрацию ИП нет»), а не по базе. Это стало причиной перейти на GigaChat-3-Pro.
- Несколько проверок оказались слишком строгими: бот писал «три года» словами или «не требуются» вместо «не нужны». Такие тесты расширены, ответы бота в них были верными.

**Известные ограничения:**
- На вопрос «Я должна 600 тысяч, мне обязательно подавать?» модель правильно называет оба условия, но иногда сама решает, что просрочка больше 3 месяцев у клиента уже есть, хотя клиент об этом не говорил. Это последняя оставшаяся ошибка.
- Модель недетерминирована: от прогона к прогону результат может отличаться на 1–2 ответа.

## Запуск

1. Получите ключ GigaChat API на [developers.sber.ru](https://developers.sber.ru). Для физлиц есть бесплатный лимит, его хватает на чат и все тесты.
2. Установите зависимости и создайте файл с ключом:
   ```
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   copy .env.example .env
   ```
   Вставьте ключ в `.env` в строку `GIGACHAT_CREDENTIALS=`.
3. Консольный чат: `python -m bot.chat`
   Команды: `/debug` показывает найденные фрагменты и их оценки, `/заявка` оформляет заявку, `/new` начинает новый диалог.
4. Telegram-бот:
   - создайте бота у [@BotFather](https://t.me/BotFather) и впишите токен в `.env` → `TELEGRAM_BOT_TOKEN`;
   - запустите `python -m bot.telegram_bot`, отправьте боту `/myid` и впишите полученный номер в `TELEGRAM_ADMIN_CHAT_ID`, чтобы получать заявки;
   - перезапустите бота.
5. Проверка качества: `python -m bot.evaluate`

## Telegram-бот

- **Для клиента:** ответы на вопросы, кнопка «Записаться на консультацию». Кнопки меняются по ходу диалога: во время заявки можно её отменить, на шаге контакта отправить номер или ник в Telegram в одно касание. Повторно оформить заявку нельзя, бот напомнит, что она уже принята.
- **Для юриста (администратора):** каждая новая заявка приходит отдельным сообщением с предварительной оценкой. Команда `/leads` присылает последние заявки и файл Excel, `/debug` показывает, какие фрагменты базы знаний нашёл поиск. Клиенты этих команд не видят.
- **Надёжность:** диалоги сохраняются на диск, поэтому перезапуск бота не обрывает заявку посередине. Контакт проверяется кодом по шаблону, а не моделью: «телефон» без номера бот не примет и попросит сам номер.

## Ограничения

- База знаний написана по общим нормам закона № 127-ФЗ и не является юридической консультацией. Цены и условия компании вымышлены.
- По умолчанию проверка SSL-сертификата GigaChat отключена для простоты демо. Для продакшена укажите сертификат НУЦ Минцифры в `GIGACHAT_CA_BUNDLE`.
